TabDance is good enough to use

October 10, 2026 · Andrew Arrow

TabDance is now good enough to use. The macOS app has live workspaces and tabs, Command-K keeps an unfinished command while clearing older output, and copying survives a terminal redraw. You can build it from source.

In the first article, my Command-K, cat file.txt, Command-A copying habit led from cmux and Rio to studying Apple Terminal’s executable. TabDance was a small AppKit prototype with a real shell and two tests. The changes since that snapshot put those everyday operations alongside the workspace layout I wanted.

Build it on your Mac

You’ll need macOS 13 or later and Xcode 16 or later, with its command-line tools selected. From a terminal:

git clone https://github.com/andrewarrow/TabDance.git
cd TabDance
./build-app.sh
open dist/TabDance.app

Or open TabDance.xcodeproj, select the TabDance scheme, and press Command-R. On the first Xcode build, allow SwiftTerm’s build information plugin when prompted. The build script uses the checked-in project and produces an ad-hoc signed app for Apple silicon and Intel Macs. XcodeGen is only needed if you change the project generator’s configuration.

The app starts your account’s login shell, so your usual shell setup comes with it. It uses Swift 6, AppKit, and SwiftTerm 1.19.0, the only external package dependency. Each shell is attached to a pseudoterminal (PTY), which lets the app exchange terminal input and output with it. SwiftTerm handles that connection, terminal emulation, and rendering; TabDance adds the workspace UI and the local editing behavior. The Apple Terminal inspection remains research material in the repository. The app is original Swift code.

A tab switch keeps the shell

Start a server in one tab, open another for edits, then switch workspaces. The server should keep running. Returning should put you back in the tab you last selected in that workspace.

TabDance gives each tab a stable UUID and keeps a separate live session for it. A workspace stores an ordered list of tabs and its selected tab’s identity. Switching changes which terminal view is visible and receives keyboard focus; the other sessions remain alive. Dragging a tab changes its position in the list while its shell stays attached to the same identity. The window tests check that switching and reordering preserve shell process IDs.

There was a smaller continuity problem in the UI itself. A background session can update its title or working directory while you’re clicking a tab. The original refresh rebuilt every tab view. If that happened between mouse-down and mouse-up, the object holding the click disappeared.

The fix compares the ordered tab IDs. If they haven’t changed, it updates the existing labels and styles in place. It also leaves the tab bar’s scroll position alone during background metadata updates. A regression test presses a tab, feeds a title and directory update from another session, then releases the mouse and checks that the intended shell gets focus. Keeping the right shell isn’t sufficient if its button moves out from under the click.

Workspaces and tabs can both be dragged into a new order. Tabs stay within their workspace and window; the tab bar shows an insertion marker and scrolls near an edge. At widths below 600 points, the workspace rail collapses and a workspace menu remains available.

Command-K keeps the line you’re editing

The important case is an unfinished command. If a prompt and command wrap across two rows, clearing the old output should keep both rows and leave the cursor at the same place in the command.

The clear operation walks backward and forward from the cursor’s row using the buffer’s wrapping flags. That identifies the whole logical line, including a continuation below the cursor. It moves those rows to the top, erases the rows beneath them, removes scrollback, and restores the cursor relative to the retained line.

It does this inside the terminal emulator. The scroll and erase sequences go directly into SwiftTerm’s parser; no Control-L is written to the shell. That keeps the result independent of how the foreground program handles Control-L. Moving existing rows also preserves their colors and metadata rather than reconstructing the command as plain text.

The distinction shows up in the tests: old output disappears from Select All, a partial command survives, a wrapped line retains its color, and no user input is sent. Clearing an alternate screen also leaves the normal buffer and bracketed-paste mode intact. These are specific behavior checks; exact newline parity and typing latency against Apple Terminal remain unmeasured.

Copy remembers the selection

Terminal programs redraw. Select hello, let the program erase that row, and Copy still ought to give you hello. TabDance stores a text snapshot when a selection is made and copies from that snapshot before falling back to the current cells:

public var copyText: String? {
    selectedTextSnapshot ?? getSelection()
}

Selecting nonempty text also copies it to the clipboard automatically. A screen redraw can invalidate the visible selection without discarding its saved string. Explicit input, a new mouse-down, or Command-K clears the snapshot. The regression test selects hello, feeds carriage return and erase-line, and checks both sides: the live buffer no longer contains the word, but Copy still does.

There’s a subtle boundary here. User typing and the terminal’s protocol replies both send bytes to the PTY. A program asking for the cursor position can trigger a reply without any user action. Treating that reply as typing would discard the selection and confuse the activity indicator. TabDance handles the two delegate paths separately: user input clears the snapshot and notifies the monitor; parser replies go straight to the process.

Held keys now repeat through AppKit too. The app registers ApplePressAndHoldEnabled = false, allowing terminal input to use macOS’s repeat delay and rate. Tests send initial and repeated events for letters, Backspace, and an arrow key and check the resulting bytes.

The next tab starts where you are

After cd, Command-T should open a shell in that directory—even if you press it before the next background poll. A shell can announce its current directory with OSC 7, an escape sequence carrying a file URL. TabDance accepts local directory updates and also polls the shell’s working directory through macOS’s libproc.

Polling alone leaves a timing gap. Immediately before creating a tab or workspace, TabDance queries the selected shell’s current directory again. The test changes directory in a real shell without sending OSC 7, waits for that command to finish, creates a tab, and checks the new shell’s directory. The new tab needn’t wait for its label to catch up.

File drops use a similarly concrete rule: insert paths and let the user finish the command. Drop local files or folders onto terminal content, or onto a tab label to select and focus that tab. TabDance inserts absolute paths with shell-special characters escaped, separated by spaces and followed by a space. It doesn’t press Enter.

If the receiving program enables bracketed paste, the drop is wrapped in paste-start and paste-end sequences. Filenames containing control characters are rejected. The drop tests use spaces, an apostrophe, shell punctuation, and Unicode, then ask both /bin/sh and /bin/zsh to parse the inserted text and compare the resulting arguments with the original paths.

A running Codex process isn’t always busy

A workspace can have a Codex process open while nothing is happening. Showing a spinner for the process’s entire lifetime would make the indicator useless.

TabDance looks for Codex beneath each shell in the local process tree, matches its session transcript by working directory and process start time, and reads new events incrementally from newline-delimited JSON (JSONL). Submitting a prompt can start the indicator while it waits for the task-start event; task_started, task_complete, and turn_aborted then drive its state. Old completion events are checked against the submission time so a previous turn can’t stop the current indicator.

Control-C clears it immediately and suppresses late events until the next submission. Newlines inside bracketed paste don’t count as submitted prompts. This is a local monitor of Codex’s transcript format; other commands don’t get this activity tracking, and changes to that format may require an update.

Try it against your own habits

These are the shortcuts to start with. The README has the full list, including numbered tab selection and keyboard reordering.

Common TabDance keyboard shortcuts
KeysAction
⌘TNew tab in the current directory
⌘⇧NNew workspace in the current directory
⌘⇧[ / ⌘⇧]Previous / next tab
⌥⌘↑ / ⌥⌘↓Previous / next workspace
⌘KClear prior output; keep the current logical line
⌘BToggle the workspace sidebar

The primary window saves workspace order, tab directories and titles, and selections to ~/Library/Application Support/TabDance/workspaces.json. Reopening starts fresh shells in those directories. Running processes and terminal output aren’t restored; secondary windows don’t overwrite the primary layout.

There are no profiles, search, or preferences yet. The terminal appearance is fixed: Menlo at 20 points, green text on opaque black, and a fixed ANSI palette. Command-W closes a tab immediately and Command-Q quits immediately; explicitly closing a window asks for confirmation when sessions are active. The app runs local shells without the macOS App Sandbox and is GPLv3.

I’m still starting with the same boring file:

printf 'alpha\nbeta\ngamma\n' > /tmp/tabdance-selection.txt
# Press Command-K, then run:
cat /tmp/tabdance-selection.txt
# Press Command-A, Command-C, and inspect the pasted text.

Then try an unfinished wrapped command, a selection erased by a redraw, and a quick cd followed by Command-T. Those cases are now implemented, with tests behind them. They’re also small enough to tell me exactly where your habits and TabDance still disagree.
