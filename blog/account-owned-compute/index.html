Reserving a machine before booting it

October 5, 2026 · Mainbrella Engineering

Two agents can request the last available slot at the same time. If each request checks capacity and then starts a machine, both can pass the check. Mainbrella’s documented lifecycle reserves capacity for the account before starting compute. A pending start already occupies a slot.

One account, one allowance

The dashboard and named API keys share an account’s containers and monthly starts. Creating a second key does not create a second quota. The account serializes reservations so concurrent launch requests cannot exceed its cap, while readiness checks can proceed in parallel. This is the distinction that makes bursts possible without treating the limit as a suggestion.

A successful reservation consumes a monthly start even if boot fails. Stopping immediately does not refund it. A request rejected because all slots are occupied does not reserve a start. An integration therefore needs to distinguish “no capacity” from “creation is still unresolved.” The container guide describes how the returned creation record resolves that uncertainty.

Where Cloudflare fits

Mainbrella runs workloads on Cloudflare Containers. Cloudflare describes each instance as a Linux container inside a Firecracker microVM, with a separate kernel and network. That is the infrastructure isolation boundary. Mainbrella supplies the account-facing API and lifecycle policy. See Cloudflare’s runtime architecture and the Mainbrella security overview.

Infrastructure capability and product capability are different contracts. Cloudflare’s network footprint does not mean a Mainbrella customer can select a compute region. Every Mainbrella plan currently uses 1/16 vCPU, 256 MiB RAM, and 2 GB of temporary disk. A higher plan raises account capacity and session duration; it does not enlarge an individual machine.

A lease with an end

Commands and terminal activity renew the idle deadline. Reading status does not. The hard session deadline and paid period recognized at creation still bound the session, even if the agent stays busy. Renewing a subscription does not extend an existing container.

After stop, the filesystem is lost. The agent should export its result before cleanup and keep durable state elsewhere. That makes the workspace suitable for bounded execution steps; a workflow that needs snapshots or persistent storage needs capabilities Mainbrella does not currently offer.
