Private services with independent machine lifecycles

Mainbrella’s Private Services prototype connects machines through named HTTP endpoints such as http://api.internal. Attach existing running machines to an account-owned network, register only the application ports you need, and detach them without stopping their peers. Your frontend can call a private backend without a public preview or a Mainbrella API key in the guest.

Daytona’s linked sandboxes place ephemeral children on their parent’s runner, with a shared network and DNS aliases. Deleting the parent deletes its children. Mainbrella’s explicit membership model gives HTTP services more flexible grouping and independent lifecycles; it is currently a local prototype, available only when networking.privateServices is true.

This is an HTTP service comparison: Mainbrella does not yet support arbitrary TCP, HTTPS, WebSockets, private IPs, or direct database protocols through Private Services. Daytona documents direct port connections. See setup and limits; no common networking benchmark establishes a speed advantage.

Choose the lifecycle your workload needs

Daytona uses usage-based pricing for compute, memory, and storage. Mainbrella includes a bounded compute allowance in each monthly plan. It fits temporary agent tasks where predictable limits matter.

Mainbrella saves filesystem snapshots explicitly; it does not provide persistent volumes or process resume. If your workload depends on Daytona-specific persistence or SDK behavior, check those requirements before migrating.

Before you start

Can I connect a frontend and backend privately?

The local Private Services prototype supports HTTP between explicitly attached machines in the same account-owned network. Register the backend as api, then call http://api.internal from the frontend. Production support is not qualified; check networking.privateServices before use. Read the setup guide.

Is Mainbrella compatible with the Daytona SDK?

No. Use Mainbrella’s SDK or HTTP API and adapt the calls your agent makes. Validate creation, execution, files, and cleanup on one workload before migrating.

Can I run a coding agent inside the container?

You can install tools and run commands in a Linux environment sized for your workload. You supply the agent’s credentials. Plan-specific idle and session deadlines still apply; Mainbrella does not yet provide a managed, always-on agent service.

How long can a machine run?

Usage billing supports sessions up to 24 hours with a 30-minute idle timeout, within your selected spending cap. Existing legacy subscriptions retain their session limits. Read the complete limits.

Can I inspect or self-host the platform?

Yes. Start with the open-source repositories and their licenses. Self-hosting requires your own infrastructure and operations; a hosted subscription uses Mainbrella’s service.
